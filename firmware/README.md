# MecanumBot firmware

Прошивка ESP32-C6: принимает команды от телефона по USB, считает кинематику меканум-колёс и управляет четырьмя моторами через два DRV8833. PlatformIO + Arduino core 3.x (платформа pioarduino).

- Дизайн: [DESIGN.md §4](../docs/DESIGN.md)
- Протокол USB (источник истины): [protocol/PROTOCOL.md](../protocol/PROTOCOL.md)
- Подключение и распиновка: [hardware/wiring.md](../hardware/wiring.md)

## Быстрый старт

```sh
cd firmware
pio test -e native                  # тесты на Mac, железо не нужно (именно -e native, см. ниже)
pio run -e esp32c6                  # сборка
pio run -e esp32c6 -t upload        # прошивка по USB-кабелю
python3 tools/usb_console.py        # консоль (pip install pyserial)
```

Окружения `platformio.ini`:

| env | Назначение |
|---|---|
| `esp32c6` | сборка и прошивка по USB (по умолчанию) |
| `esp32c6_ota` | прошивка по Wi-Fi через ArduinoOTA — заработает на этапе 7 |
| `native` | Unity-тесты чистых библиотек на хосте |

Тесты в `test/` — только для хоста: у них свой `main()`, они читают `../protocol/vectors.json` с диска и используют ArduinoJson. Поэтому в `esp32c6` стоит `test_ignore = *`, и голый `pio test` (он берёт `default_envs = esp32c6`) ничего не запускает — всегда указывайте `-e native`. `native` не добавлен в `default_envs`, иначе `pio run` помечал бы его как FAILED: собирать там нечего.

Плата должна подключаться через нативный USB (VID `0x303A`, PID `0x1001`), а не через USB-UART мост.

## Первый запуск

Колёса в воздухе, физический выключатель VM под рукой (DESIGN.md §7).

1. Прошить: `pio run -e esp32c6 -t upload`.
2. `python3 tools/usb_console.py` — должна появиться строка `[hello] proto 1 fw 0.1 reset=... boots=N`.
3. `tel on` — проверить `vm` (~3600 мВ при buck 3,6 В) и `rx≈40/s`.
4. По одному каналу: `raw 0.3 0 0 0`, `raw 0 0.3 0 0`, … — записать, какое колесо крутится и куда (понадобится для калибровки `map`/`invert`).
5. `stop`, затем `drop` — консоль покажет время до failsafe (~300 мс), светодиод станет красным. `idle` возвращает «пульс».

Результаты измерений — в [docs/measurements.md](../docs/measurements.md).

## Консоль `tools/usb_console.py`

Шлёт DRIVE 40 Гц (иначе сработает failsafe), PING раз в секунду, печатает LOG, ACK, HELLO_ACK и по запросу телеметрию. Кодек берётся из эталонной реализации `protocol/gen_vectors.py`. Порт находится автоматически, иначе `--port /dev/cu.usbmodemXXXX`. DTR/RTS не переключаются, чтобы C6 не ушёл в загрузчик.

| Команда | Действие |
|---|---|
| `d VX VY W` | ехать (vx вправо, vy вперёд, w по часовой; −1…1) |
| `f` / `b` / `l` / `r` / `cw` / `ccw` `[S]` | вперёд / назад / влево / вправо / разворот, скорость S (0,5) |
| `raw M1 M2 M3 M4` | MOTOR_RAW по физическим каналам, в обход калибровки |
| `idle` | DRIVE с enable=0 — только «пульс» |
| `stop`, `s` | STOP ×3, затем idle |
| `drop` | перестать слать команды и измерить время до failsafe |
| `limit X` | лимит скорости 0…1 (по умолчанию 0,3), умножается на все команды |
| `hello`, `ping` | рукопожатие / последний RTT |
| `cfg` | прочитать конфигурацию |
| `set K=V …` | изменить поля и отправить CONFIG, напр. `set invert=0,1,0,1 min_duty=20`; поля — ниже и `help set` |
| `tel [on\|off]` | печать телеметрии |
| `raw-log` | печать всех принятых кадров |
| `reboot` | перезагрузка ESP32 |
| `quit`, `q`, Ctrl-D | STOP и выход |

Поля `set` (PROTOCOL.md §4.4). Сначала `cfg`: изменённые поля уходят одним CONFIG, затем конфигурация перечитывается. Списки — 4 значения через запятую без пробелов, по колёсам FL, FR, RL, RR. Недопустимое значение отклоняет весь CONFIG (ACK ERR), ничего не сохраняется. Конфигурация хранится в NVS и переживает перезагрузку.

| Поле | По умолчанию | Допустимо | Смысл |
|---|---|---|---|
| `map` | `0,1,2,3` | перестановка 0…3 | какой физический канал M1–M4 крутит каждое колесо |
| `invert` | `0,0,0,0` | 0/1 | 1 — развернуть направление колеса (применяется до `map`) |
| `trim` | `100,100,100,100` | 50…100 % | множитель скорости колеса, выравнивание редукторов |
| `max_duty` | 100 | 1…100 % | максимальный PWM (ограничивает и `raw`) |
| `min_duty` | 15 | 0…`max_duty`−1 % | PWM, с которого начинает крутиться колесо |
| `slew_ms` | 250 | 0…2000 мс | разгон 0→100 %; остановка всегда мгновенная |
| `brake` | 1 | 0/1 | 1 — торможение при STOP/failsafe, 0 — выбег |
| `failsafe_ms` | 300 | 100…1000 мс | стоп без DRIVE/MOTOR_RAW дольше этого |
| `pwm_hz` | 20000 | 1000…30000 Гц | частота PWM |
| `version` | 1 | только 1 | версия структуры, не менять |

`raw` идёт в обход `map`, `invert`, `trim` и `min_duty`; `d`, `f`/`b`/… проходят через все поля.

## Структура

```
firmware/
├── platformio.ini
├── include/config.h       — все пины и константы (только здесь)
├── src/main.cpp           — setup()/loop(), связывает модули
├── lib/
│   ├── protocol/          — кадры, CRC-8, парсер, раскладки payload     [чистый C++]
│   ├── kinematics/        — меканум-микширование, калибровка            [чистый C++]
│   ├── failsafe/          — сторожевой таймер команд                    [чистый C++]
│   ├── motion/            — плавный разгон, переключение H-моста        [чистый C++]
│   ├── controller/        — обработка кадров, режимы, ACK, CONFIG       [чистый C++]
│   ├── link/              — USB CDC: приём кадров, неблокирующая отправка  [Arduino]
│   ├── motors/            — DRV8833 через LEDC, nFAULT, nSLEEP           [Arduino]
│   ├── storage/           — Config и счётчик загрузок в NVS              [Arduino]
│   └── telemetry/         — TELEMETRY 10 Гц, измерение VM                [Arduino]
├── test/                  — native-тесты, векторы из ../protocol/vectors.json
└── tools/usb_console.py
```

Логика живёт в чистых библиотеках и покрыта тестами; Arduino-модули — тонкие обёртки над железом. `lib/motion` и `lib/controller` добавлены сверх DESIGN.md §4.1 именно для этого. `ota_usb` и `wifi_ota` появятся на этапе 7.

## Как это работает

Один цикл `loop()` без RTOS-задач и без `delay()`:

```
usb.poll()            → парсер → controller.onFrame()
checkHost()           → HELLO_ACK при подключении хоста
controller.tick()     → failsafe
controller.output()   → кинематика (DRIVE) или сырые каналы (RAW) → цель по каналам
motors.update()       → разгон (slew) → H-мост → LEDC
telemetry             → раз в 100 мс
```

- **Failsafe.** Активен с момента старта. Любой DRIVE (в том числе enable=0) или MOTOR_RAW сбрасывает таймер; через `failsafe_ms` (300 мс) без них моторы мгновенно останавливаются.
- **Разгон.** Ограничен только рост скорости: 0→100 % за `slew_ms` (250 мс). Торможение, STOP, failsafe и смена направления срабатывают сразу, разворот затем разгоняется с нуля.
- **Моторы.** Один канал LEDC на мотор (у C6 их 6): вперёд — PWM на IN1, назад — PWM на IN2. Остановка — торможение (оба входа HIGH) или выбег при `brake=0`. Между двумя режимами — 2 мс выбега, без блокировки цикла.
- **USB.** Кадр пишется только если в буфере есть место, иначе пропускается; LOG — только при запасе 64 байта. `Serial.print` не используется: порт занят протоколом.
- **HELLO_ACK** уходит при каждом подключении хоста к порту (после старта и после переподключения). Перезагрузку отличают по росту `reset_count`.
- **Watchdog** задач 2 с, brownout-детектор включён. Если перенастроить WDT не удалось, при подключении хоста приходит LOG error.

Светодиод (WS2812 на GPIO8): красный — failsafe, синий — связь есть, стоим, зелёный — едем.

## Правила разработки

Полный список — в [CLAUDE.md](../CLAUDE.md). Коротко:

- Пины и константы — только в `include/config.h`.
- Никаких `Serial.print` и `delay()`; логи — через `controller.log()` (LOG-кадры).
- Новая логика — в чистые библиотеки с native-тестами.
- Изменение протокола: `PROTOCOL.md` → `gen_vectors.py` → `python3 protocol/gen_vectors.py` → код → тесты.
- Любой путь, крутящий мотор, подчиняется failsafe.

## Неполадки

| Симптом | Что проверить |
|---|---|
| консоль: `not found` | кабель с данными; порт — нативный USB (`303a:1001`), а не UART-мост; `--port` |
| нет `[hello]` | переоткрыть консоль; `hello` вручную |
| `rx` < 40/s, растёт `crc_err` | длина/качество кабеля, помехи от проводов моторов |
| мотор не крутится при малых значениях | поднять `min_duty` (`set min_duty=20`) |
| `vm` проседает ниже 3200 мВ | перегрузка моторов или OTG-лимит телефона (DESIGN.md §11) |
| ESP32 перезагружается при старте моторов | brownout: конденсаторы на VM/5 В, снизить `limit`, увеличить `slew_ms` |
| флаги `FA`/`FB` в телеметрии | nFAULT драйвера: перегрузка по току или перегрев |
